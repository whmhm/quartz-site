# 三级等保项目中 Cookies 安全问题与应对经验总结

## 一、测评暴露的 Cookies 安全核心问题

在三级等保测评阶段，Cookies 相关漏洞被列为高风险整改项，具体问题如下：

### 1. HttpOnly 属性缺失

未限制前端 JS 脚本访问 Cookie，攻击者可通过 XSS 攻击注入恶意脚本，窃取用户 SessionID 等敏感信息，直接威胁账号安全。

### 2. Secure 属性未启用

Cookies 在 HTTP 协议下明文传输，中间人可通过网络嗅探工具拦截数据，存在 Cookie 被篡改、伪造的风险。

### 3. SameSite 属性配置空白

未限制跨域场景下 Cookie 携带规则，攻击者可利用 CSRF 攻击，伪造用户请求执行转账、修改密码等操作。

### 4. 过期时间设置不合理

Session Cookie 未设置自动过期，非核心 Cookie 长期有效，即使用户退出登录，Cookie 仍可能被复用，增加信息泄露时长。

## 二、针对性安全策略与落地配置

### （一）Cookies 属性强制配置

#### 1. HttpOnly 与 Secure 配置

- **效果**：前端 `document.cookie` 无法读取 SessionID，且 Cookie 仅在 HTTPS 通道传输。

#### 2. SameSite 属性场景化配置

- **核心业务（登录、支付接口）**：设置 `SameSite=Strict`，仅允许同域请求携带 Cookie，杜绝跨域 CSRF 风险；
- **普通浏览场景（如文章浏览）**：设置 `SameSite=Lax`，兼容部分跨域跳转需求（如从第三方链接跳转至项目页面），平衡安全性与用户体验。

#### 3. 过期时间精细化管控

- **Session Cookie**：设置 30 分钟过期（`Max-Age=1800`），用户无操作时自动失效；
- **非核心 Cookie（如主题偏好）**：过期时间不超过 24 小时（`Max-Age=86400`），避免长期留存风险。

### （二）XSS 攻击联动防御（配合 Cookies 防护）

XSS 攻击是窃取 Cookie 的主要手段，需构建"四层防护体系"：

1. **输入过滤**：前端通过正则限制特殊字符（如 `<script>`），后端使用 OWASP AntiSamy 工具对用户输入进行净化，双重拦截恶意脚本。
2. **输出编码**：根据输出位置选择编码方式——
   - HTML 页面输出时转义 `<`、`>` 等字符；
   - JS 脚本中使用 `JSON.stringify()` 转义特殊符号；
   - URL 参数通过 `URLEncoder.encode()` 处理。
3. **CSP 策略加固**：服务端添加响应头，仅允许加载信任源的脚本，阻断恶意脚本执行：

   ```http
   Content-Security-Policy: default-src 'self'; script-src 'self' https://trusted.cdn.com;
   ```

4. **DOM 操作规范**：禁止使用 `innerHTML`、`document.write()` 等危险 API，改用 `textContent`、`setAttribute()` 等安全方法，避免 DOM 型 XSS 攻击。
